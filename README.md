# SPARK 작업 접수 대시보드 v9.10

React, TypeScript, Supabase, Vercel로 구성한 작업 접수·회원·단계별 정산 대시보드입니다.

## v7 변경사항

### 회원가입 문구

- 회원가입 화면에는 추천 코드 입력란만 유지합니다.
- 가입 성공 안내는 `가입 신청이 완료되었습니다. 승인 후 로그인할 수 있습니다.`로 통일했습니다.
- 승인 담당자나 서버 동기화 구조를 회원가입 화면에 설명하지 않습니다.
- 실제 수취인을 관리자라고 오표기하지 않고, 일반 회원 화면에서는 `입금 계좌`, `정산 계정`, `작업 정산 내역`처럼 중립적인 항목명을 사용합니다.

### 정산 집계

정산 금액은 주문의 최종 판매가가 아니라 `payment_steps`의 실제 납부 단계 기준으로 계산합니다.

- 대행사·총판의 `입금 대기 금액`: 본인이 처리해야 하는 미확인 정산 단계 합계
- `입금 완료 금액`: 본인이 처리한 확인 완료 단계 합계
- `총 접수 금액`: 위 두 금액의 합계
- `입금 받은 금액`: 하위 대행사에게 실제로 받아 확인한 단계 합계
- 관리자의 금액 카드: 관리자에게 들어오는 마지막 정산 단계만 집계

따라서 하위 작업의 최종 판매가가 관리자 정산금액으로 중복 계산되지 않습니다.

### 정산 화면

- 하위 대행사 입금확인 표의 칸 너비와 행 높이를 줄였습니다.
- 입금확인 버튼이 한 화면에서 보이도록 고정 열 너비를 적용했습니다.
- 관리자 입금확인 영역은 가로 전체를 사용합니다.
- 관리자 정산 표의 등록자는 아이디 대신 관리자용 그룹명으로 표시합니다.
- 관리자 작업 결제 표의 금액도 최종 판매가가 아닌 관리자에게 실제 입금되는 정산액으로 표시합니다.
- 하위 계층에서 접수한 작업은 `그룹명 하위`로 표시합니다.

### 시작일 지정

- 개별 작업 접수 시 시작일을 직접 선택할 수 있습니다.
- 최소 선택일은 한국 시간 기준 익일입니다.
- 종료일은 선택한 시작일부터 구동일수를 포함해 계산합니다.
- 대량접수 XLSX 양식에도 `시작일` 열을 추가했습니다.

대량접수 열:

```text
상호명
대표키워드
플레이스URL
일일수량
구동일수
시작일
메모
```

### 진행률

- 입금완료 작업은 지정 시작일 자정에 자동으로 `구동중`으로 바뀝니다.
- 관리자가 시작일 전이라도 수동으로 `구동중`으로 변경하면 즉시 게이지가 시작됩니다.
- 작업별·날짜별 고정 난수를 사용하므로 새로고침해도 진행률이 튀거나 감소하지 않습니다.
- 하루 동안 작은 단위로 천천히 증가하며 작업별로 23:00~23:50 사이에 100%가 됩니다.
- 타수 차이는 반영하지만 완료 속도 차이는 작게 유지했습니다.

### 대행사·총판 대시보드

구동중 작업을 작은 카드로 표시합니다.

- 상호명
- 대표 키워드
- 진행률 게이지

플레이스 URL과 별도 예상 완료시간은 표시하지 않습니다.

## 실행

```bash
npm install
npm run dev
```

운영 빌드 확인:

```bash
npm run build
```

## 서버 업데이트

기존 v6 Supabase를 사용 중이라면 `schema.sql`이나 `update_v6.sql`을 다시 실행하지 않습니다.

다음 순서로 적용합니다.

```text
1. supabase/update_v7.sql 실행
2. supabase/verify_v7.sql 실행
3. 프런트엔드 파일 교체
4. npm install
5. npm run build
6. GitHub main 브랜치에 push
7. Vercel Production 배포 확인
```

자세한 절차는 [DEPLOYMENT.md](./DEPLOYMENT.md)를 확인합니다.

## 주요 파일

```text

src/features/SettlementPage.tsx    단계별 정산과 집계

supabase/update_v7.sql             v6 → v7 DB 마이그레이션
supabase/verify_v7.sql             설치 확인
```

## 보안 및 운영 원칙

- 브라우저에는 Supabase Publishable key만 사용합니다.
- Secret key, service-role key, 데이터베이스 비밀번호는 프런트엔드와 GitHub에 넣지 않습니다.
- 기존 운영 데이터가 있는 프로젝트에서는 테이블 삭제나 초기화 SQL을 실행하지 않습니다.
- DB 구조 변경은 `supabase/migrations`에 버전별 SQL로 기록합니다.
