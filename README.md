# SPARK 작업 접수 대시보드 v6

React + TypeScript, Supabase, Vercel로 구성한 작업 접수·회원 계층·정산 관리 대시보드입니다.

## v6 핵심 변경

### 추천 회원 계층

- 회원가입에 선택 입력인 `추천인 아이디 또는 코드` 추가
- 추천인 없이 가입: 기존처럼 관리자가 대행사·총판, 단가, 관리자용 그룹명을 지정해 승인
- 추천인을 입력해 가입: 역할을 자동으로 `대행사`로 지정
- 추천 가입자는 관리자 승인이 아니라 **직접 추천인 승인** 대상
- 대행사와 총판 모두 자신의 직접 하위 대행사를 승인·반려하고 1타당 단가를 지정
- 하위 대행사도 다시 자신의 하위 대행사를 만들 수 있음
- 각 회원의 추천 코드는 `내 정보`와 `회원관리`에서 확인

### 단가 계층

하위 단가는 반드시 상위 단가보다 높아야 합니다.

```text
관리자 원가 20원
총판 단가 30원
대행사 A 단가 40원
대행사 B 단가 55원
```

주문이 접수되면 각 단계의 정산 금액은 해당 단계의 1타당 단가로 고정됩니다. 회원 단가를 나중에 수정해도 이미 접수된 주문과 정산 단계는 바뀌지 않습니다.

### 단계별 입금 확인

예를 들어 `대행사 B → 대행사 A → 총판 → 관리자` 구조라면 주문마다 다음 정산 단계가 생성됩니다.

```text
대행사 B가 대행사 A에게 결제
대행사 A가 총판에게 정산
총판이 관리자에게 정산
```

각 수취인은 정산 탭에서 실제 입금을 확인한 뒤 `입금확인`을 누릅니다. 모든 단계가 확인되어야 작업 상태가 `입금완료`로 변경됩니다.

### 입금 계좌

- 관리자 직속 회원은 관리자 정산 계좌를 확인
- 추천 가입 회원은 직접 추천인의 계좌를 확인
- 대행사·총판은 `내 정보`에서 하위 대행사에게 보여 줄 계좌를 등록
- 계좌가 없는 회원은 하위 대행사를 승인할 수 없음

### 관리자용 그룹명

- 관리자가 직속 회원을 승인할 때 업체 식별용 그룹명을 입력
- 하위 추천 회원은 상위 그룹명을 자동 상속
- 그룹명은 관리자 화면에만 표시
- 관리자 작업 목록에는 등록자, 직접 상위회원, 그룹명이 함께 표시

### 대량 작업 접수

대행사·총판 작업접수 화면에 다음 버튼이 추가되었습니다.

- `대량접수 양식`: XLSX 템플릿 다운로드
- `대량작업접수`: 작성한 XLSX 업로드

템플릿 입력 열:

```text
상호명
대표키워드
플레이스URL
일일수량
구동일수
메모
```

업로드 시 모든 행의 URL, MID, 수량, 기간을 먼저 검증하며 한 번에 최대 500건까지 접수합니다. 검증 오류가 있으면 행 번호와 오류 내용을 표시하고, 오류가 없는 경우에만 전체를 한 트랜잭션으로 접수합니다.

### 자정 자동 구동과 진행률

- 입금완료 작업은 시작일 한국 시간 자정 이후 `구동중`으로 자동 변경
- 자동 시작 Cron은 1분 간격으로 확인하므로 자정 후 최대 약 1분 이내 반영
- 진행률은 00:00부터 하루 동안 매우 천천히 증가
- 주문번호·날짜·타수를 시드로 사용하여 새로고침해도 같은 시점에는 같은 값
- 같은 타수도 주문마다 진행 패턴과 완료 시각이 다름
- 타수에 따른 속도 차이는 작게 적용
- 작업별로 23:00~23:50 사이 100% 도달
- 종료일 다음 날 자동 `만료`

진행률은 화면 시연용 계산값입니다. 실제 작업 서버와 연결할 때는 `src/lib/progress.ts`를 실측 완료 수량 API로 교체해야 합니다.

### 관리자 알림

관리자 알림센터에 다음 이벤트가 저장됩니다.

- 추천인 없는 회원가입 신청
- 추천 코드를 사용한 회원가입 신청
- 추천인의 하위 회원 승인·반려 처리
- 개별 작업 접수
- 대량 작업 접수에 포함된 각 작업
- 전체 정산 단계 완료로 작업이 입금완료 처리된 경우

## 실행

```bash
npm install
npm run dev
```

프로덕션 빌드 확인:

```bash
npm run build
```

## 실행 모드

### 데모 모드

Supabase 환경 변수가 없으면 브라우저 `localStorage`로 동작합니다.

### 서버 동기화 모드

프로젝트 루트의 `.env.local`:

```env
VITE_SUPABASE_URL=https://프로젝트참조.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_실제키
```

기존 `.env.local`은 v6에서도 그대로 사용합니다.

## 기존 v5 서버 업데이트

운영 중인 v5 Supabase에는 `schema.sql`을 다시 실행하지 않습니다.

실행 순서:

1. `supabase/update_v6.sql`
2. `supabase/cron_v6.sql`
3. `supabase/verify_v6.sql`
4. v6 프런트엔드를 GitHub에 push
5. Vercel Production 배포 확인

자세한 절차는 `DEPLOYMENT.md`를 확인하세요.

## 새 Supabase 프로젝트 설치

처음 만드는 프로젝트라면 다음 파일을 사용합니다.

1. `supabase/schema_fresh_v6.sql`
2. 관리자 계정 가입 후 `supabase/bootstrap_admin.sql`
3. `supabase/cron_v6.sql`
4. `supabase/verify_v6.sql`

## 주요 파일

```text
src/features/AuthPage.tsx          추천 코드 회원가입
src/features/MembersPage.tsx       직접 하위 회원 승인·단가 관리
src/features/MyInfoPage.tsx        추천 코드·하위 결제 계좌
src/features/SettlementPage.tsx    단계별 입금 확인
src/features/OrdersPage.tsx        개별·대량 작업 접수
src/lib/progress.ts                자정~밤 진행률 계산
supabase/update_v6.sql             기존 v5 DB용 마이그레이션
supabase/schema_fresh_v6.sql       신규 DB 전체 설치본
supabase/cron_v6.sql               자정 자동 시작·자동 만료
supabase/verify_v6.sql             설치 검증
```

## 보안 규칙

- 비밀번호는 Supabase Auth에만 저장
- 브라우저에는 Publishable key만 사용
- 회원은 본인, 직접 상위회원, 직접 하위회원 정보만 조회
- 회원 승인 함수에서 직접 추천 관계를 재검사
- 하위 단가가 상위 단가보다 높도록 DB 함수에서 재검사
- 정산 단계는 입금자·수취인·관리자만 조회
- 입금 수취인만 해당 단계를 확인 가능
- 그룹명은 관리자 화면에서만 표시하고 전체 회원·주문 조회는 관리자에게만 제공
